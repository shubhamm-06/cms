# Public visibility and content feeds

Implementation report for 5 November 2026. No SQL, migrations, schema changes, direct Supabase connection, service-role reads or edits under app/dashboard or app/owner were made. Canonical construction, sitemap behavior and enquiry interactions retain their existing logic.

## Behavior

- The shared public entity lives in src/lib/business.ts. Root markup is Organization with a stable #organization ID, official logo, public email, configured WhatsApp/phone contact and Goa service area. There is no office address. sameAs is omitted until verified URLs are available. The duplicate homepage ProfessionalService block is removed.
- /property-management-goa introduces the company, property types, Goa service area and owner starting steps in two sentences. A shared inclusion list and Service markup accompany the existing detailed services. Existing Q&A arrays feed the visible answers and FAQPage markup.
- Property pages have a visible data-backed At a glance paragraph, VacationRental and Home > Stays > Property breadcrumbs. Known public capacity, amenities and times are included. Editorial registry names/introductions match visible content. No rating, review, offer, rate or availability is added.
- /booking has a server-rendered explanation with areas derived from its returned catalogue and ItemList markup for those same properties.
- Both text feeds use loadPublicCatalogue and, for full details, loadPublicPropertyDetail. These retain the existing anon-only public views and 60-second caches. No new database query exists. Failed reads produce static sections only; withdrawn detail rows are omitted. The text/plain UTF-8 responses use max-age=0, must-revalidate so an additional response cache cannot extend the data TTL.
- robots.txt preserves the wildcard group and adds the twelve requested individual agents, each with the identical shared disallow list. No user-agent-dependent content is added.

### schema.org shape review

Organization/ContactPoint, Service/provider/areaServed, FAQPage/Question/Answer, ItemList/ListItem, BreadcrumbList and VacationRental shapes were reviewed against the official vocabulary. Capacity and bedroom/bathroom counts live on the nested Accommodation. JSON serialization escapes < in public descriptions. This is vocabulary and source-level validation, not an online Rich Results submission or a claim about search eligibility.

The requested name numberOfBathroomUnits is not a schema.org term. The implementation uses numberOfBathroomsTotal for whole counts, whose range is Integer. Fractional bathroom values use Accommodation.additionalProperty with a PropertyValue instead of an invented rounded count.
